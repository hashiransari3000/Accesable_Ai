ACCESSABLE AI - ARCHITECTURE
============================

1. DESIGN PRINCIPLES
--------------------
  - Modular: business logic lives in service modules under modules/;
    the UI layer stays thin and delegates to services.
  - Lazy loading: heavy models (YOLO, EasyOCR) load only when first
    needed and are cached in memory for reuse.
  - CPU-first: default inference settings target a laptop without a GPU.
  - Local-only: no network calls at request time (model download happens
    once, on first use, and is documented).
  - Testable: pure functions (position analysis, graph algorithms,
    announcement logic) are separated from I/O and UI.

2. MODULE RESPONSIBILITIES
--------------------------
  app.py
      Streamlit entry point. Owns page routing, session state, and calls
      into modules/ and ui/. Contains no detection/OCR/graph logic.

  modules/object_detection.py
      Wraps Ultralytics YOLO (yolo11n nano, AGPL-3.0, COCO-80 classes).
      Loads the model lazily on first use and caches it in a module-level
      cache (never reloaded per interaction). Runs CPU inference
      (imgsz 640, device="cpu"), then returns a structured result:
      detections [{label, confidence, bbox}], an annotated PNG preview,
      image size, inference time in ms, and an error field. Pure helpers
      (filter_by_confidence, clamp_bbox, format_label) are separated for
      unit testing without a model. Weights download once to
      models/yolo11n.pt on first use, then work offline. Knows nothing
      about the UI.

  modules/position_analysis.py
      Pure functions. Maps a bounding box to coarse screen-relative
      position: horizontal (left / center / right) and vertical
      (upper / middle / lower), classified by box centre against image
      thirds. Returns cautious phrasing strings ("appears on the left
      side of the image") and never distance or safety claims.

  modules/announcement_manager.py
      Pure logic. Prioritizes detections (confidence + a small
      usefulness boost for classes like "person"), caps the spoken list
      (default 4 items), and builds concise phrases per object plus a
      summary. Also provides RepetitionGuard, a cooldown-based
      deduplication guard for continuous sources (camera, Phase 5) so
      the same unchanged object is not announced every frame.

  modules/voice_assistant.py
      Wraps pyttsx3 (+ eSpeak NG on Linux) for fully offline speech.
      speak / stop / replay / rate control. Speech runs in a daemon
      thread (Streamlit scripts must not block); a fresh engine is
      created per utterance because pyttsx3 engines are not thread-safe.
      Availability is probed once and cached; if TTS is missing the UI
      shows the text summary plus an actionable setup hint instead of
      crashing. Speech is user-triggered only; nothing auto-plays.

  modules/text_recognition.py
      Wraps EasyOCR (English). Loaded on demand only: the reader is not
      created until the user presses "Extract text", then cached for the
      process lifetime. Returns an explicit result state: error
      (unreadable image / load failure / OCR failure), is_empty (clean
      run, no text found - not an error), or success (joined text,
      per-region confidence, processing time). Weights are cached once
      by EasyOCR in ~/.EasyOCR (outside the repository). Never runs
      continuously on video frames.

  modules/camera.py
      Camera capture helper for the live mode. Deliberate activation
      only, frame throttling, and guaranteed resource release on stop.

  modules/camera.py
      Controlled live camera capture (Phase 5). Activation requires a
      deliberate user action; the app never starts the camera on load.
      A background daemon thread grabs frames at a modest target FPS
      (15) and keeps only the latest frame. Capture rate is fully
      decoupled from inference: detection runs per user-triggered
      snapshot only, and OCR never runs on camera frames. stop() is
      idempotent and releases the device; the UI also stops the camera
      on page change. No-device, permission-denied, and device-lost
      paths produce readable fallback messages pointing to image upload.

  modules/navigation/graph_data.py
      Parses and validates the fictional sample building map from
      assets/sample_maps/sample_building.txt (human-readable "node" and
      "edge" lines with floor-plan coordinates). Also provides the
      euclidean heuristic builder, documented as admissible because edge
      weights equal straight-line endpoint distances.

  modules/navigation/bfs.py
      Hand-written BFS: FIFO deque, visited set via parent pointers,
      backwards path reconstruction. Minimizes hops, ignores weights.
      Returns path (or None when unreachable) plus the exploration order.

  modules/navigation/astar.py
      Hand-written A* with heapq priority queue: f(n) = g(n) + h(n),
      settled set, stale-entry skipping, insertion-counter tie-breaking.
      Uses the admissible euclidean heuristic (zero heuristic supported,
      i.e. Dijkstra behaviour). Minimizes weighted distance.

  modules/navigation/route_service.py
      Caches the parsed sample graph, runs BFS and/or A*, and converts
      every outcome (route, unreachable, invalid node, failure) into an
      explicit RouteResult with cost, hops, explored nodes, and timing
      for the comparison view.

  ui/components.py, ui/styles.py
      Shared UI components (status banners, buttons, result cards) and
      the design tokens (colours, spacing, typography) in one place.

3. DATA FLOW (SCENE ASSISTANT)
------------------------------
  Uploaded image -> validation -> OpenCV preprocessing (resize,
  preserve aspect ratio) -> YOLO inference -> structured detections
  -> position analysis -> announcement manager (prioritize + concise
  summary) -> UI result list / annotated preview / text summary
  -> user-triggered TTS (background thread).

4. DATA FLOW (READ TEXT)
------------------------
  Uploaded image -> validation -> EasyOCR (loaded on demand) ->
  extracted text + confidence -> result panel -> user-triggered TTS.

5. DATA FLOW (NAVIGATION DEMO)
------------------------------
  Sample map file -> graph -> BFS and A* -> route, explored set, cost,
  timing -> route visualization + comparison table + disclaimer.

7. DEPENDENCIES
---------------
  Python packages (pinned in requirements.txt):
    streamlit, ultralytics (YOLO), opencv-python, pyttsx3, easyocr,
    pillow, networkx, pytest

  System packages (documented in docs/SETUP_GUIDE.txt):
    espeak-ng (offline speech backend on Linux)

  Model files:
    YOLO nano weights are downloaded automatically on first inference
    and cached locally (see models/README.txt). They are NOT committed
    to the repository.

8. ERROR HANDLING POLICY
------------------------
  Exceptions are caught at module boundaries and converted into
  actionable, user-facing states (error message + suggested fix).
  No broad silent exception handling. Missing optional components
  (camera, TTS, OCR model) degrade the app rather than crash it.
