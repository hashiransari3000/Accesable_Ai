ACCESSABLE AI - ARCHITECTURE
============================

1. DESIGN PRINCIPLES
--------------------
  - Offline first: no cloud AI APIs, no analytics, no accounts.
  - Local CPU inference with lazy model loading and caching.
  - Modular: UI code calls service modules; service modules know nothing
    about Streamlit and are unit-testable.
  - Explicit states: loading, success, empty, warning, error. Empty is
    never presented as an error.
  - Honest limitations: confidence is not safety, image position is not
    physical space, and relative depth is not metres.

2. COMPONENTS
-------------
  app.py
      Streamlit entry point. Page routing, session state, and calls into
      modules/ and ui/. Contains no detection, OCR, or graph logic.

  modules/object_detection.py
      Ultralytics YOLO11n (COCO-80, CPU). Lazy loading, module-level cache,
      a shared inference lock for concurrent camera/briefing requests, and
      structured DetectionResult output with optional annotation. Pure
      helpers (confidence filtering, box clamping) are tested without a
      model. Weights: models/yolo11n.pt.

  modules/open_vocabulary.py
      YOLO-World v2 for free-text prompts (door, stairs, ramp, etc.).
      Parses and de-duplicates prompts (max 30) and applies set_classes
      only when the prompt set changes. Scores are lower than fixed-class
      detection; failures stay in result.error while the app remains
      usable. Weights: models/yolov8s-worldv2.pt plus a CLIP text encoder
      in weights/clip/.

  modules/depth_estimation.py
      Optional relative proximity. Lazy-loads Depth Anything V2 Small via
      transformers (CPU), interpolates predicted depth to image size, and
      maps each detection to a band (very close / close / mid-distance /
      far). Relative within one image only; a failure returns a warning
      and never discards detections.

  modules/rubiks_detector.py
      Classical OpenCV heuristic for Rubik's cube faces. Builds a
      saturated-colour mask, takes the convex hull of a valid
      quadrilateral (or its minimum-area rectangle), warps it to 300x300,
      and classifies the nine tile centres by HSV vote. Requires at least
      seven classified tiles, three distinct colours, and a pattern score
      of 0.55. Emits a Detection with source "color-grid". Solved
      single-colour faces are rejected by design.

  modules/scene_tracker.py
      Pure change detection for camera auto-briefing. Objects are keyed
      by label plus a coarse 3x3 screen region. New objects must be seen
      in consecutive updates before being announced; gone objects are
      reported after consecutive misses. Unconfirmed flashes are ignored.
      Output is a text summary that is also spoken.

  modules/position_analysis.py
      Pure functions mapping a bounding box to coarse image-relative
      position (left / center / right and optionally upper / middle /
      lower). Never claims physical distance or safety.

  modules/announcement_manager.py
      Prioritises detections, caps the spoken list, and builds concise
      cautious phrases. Includes a cooldown guard for continuous sources
      so unchanged objects are not announced repeatedly.

  modules/voice_assistant.py
      Offline pyttsx3 + eSpeak NG speech with speak / stop / replay / rate
      control. Utterances run in a daemon thread; a fresh engine is created
      per utterance because pyttsx3 engines are not thread-safe. Speech is
      user-triggered or explicitly enabled; text output always exists.

  modules/runtime.py
      Detects whether the app is running locally or on a hosted platform
      (Streamlit Community Cloud, Hugging Face Spaces, or an explicit
      ACCESSABLE_HOSTED flag). Hosted mode switches to browser speech and
      browser camera snapshots because server audio and live camera access
      are unavailable there.

  ui/browser_speech.py
      Hosted speech via the Web Speech API in a Streamlit component. The
      page always shows the same message as text and offers an explicit
      Stop control; speech remains user-triggered or opt-in.

  modules/text_recognition.py
      EasyOCR English, loaded only when requested and cached for the
      process lifetime. Distinguishes "no text found" (empty) from errors
      and returns per-region confidence. Never runs on camera frames.

  modules/camera.py
      Controlled live camera capture. A background daemon thread keeps
      only the latest frame; activation is deliberate and stop() is
      idempotent. Detection runs per snapshot or auto-briefing interval.
      No-device and permission errors produce fallback instructions.

  modules/image_validation.py
      Pure upload validation: allowed formats, a 10 MB size limit before
      decoding, and decode checks with actionable messages.

  modules/navigation/
      graph_data.py parses and validates the fictional two-floor map
      (floors, node kinds/tags, edge type/width/crowd). bfs.py and astar.py
      are hand-written searches with optional allowed/cost callables.
      profiles.py enforces Fastest / Step-free / Quiet preferences;
      scenarios.py supplies simulated closure presets; instructions.py
      builds turn-by-turn text, ETAs, and spoken summaries; route_service.py
      is the UI-facing planner and explanation layer. All unit-tested.

  ui/styles.py        Design tokens, global CSS, accessible focus styles.
  ui/components.py    Shared headers, banners, cards, and status pills.
  ui/map_view.py      Two-floor Plotly schematic with route, explored-node,
      closure, and floor-change overlays; clicking nodes/edges is decoded
      by the navigation page.

3. DATA FLOW
------------
  Image upload
      Streamlit uploader -> image_validation -> object_detection /
      open_vocabulary -> optional depth -> optional Rubik's cube check ->
      results table + annotated preview -> announcement_manager ->
      voice_assistant.

  Live camera
      camera.py thread -> latest frame -> preview fragment (display only)
      -> manual capture or auto-briefing fragment -> object_detection ->
      scene_tracker -> change summary -> text log + optional speech.

  Read Text
      Uploader -> image_validation -> text_recognition (on demand) ->
      text block, copy/download, speech.

  Navigation
      graph_data -> route_service -> profiles/scenarios -> bfs/astar ->
      interactive Plotly map, metrics/explanation, profile comparison,
      BFS-vs-A* comparison, and a guided walk-through with optional speech.
      Map clicks update start/destination or simulated closures and trigger
      an automatic rerun; nothing is live location data.

4. SAFETY AND DEGRADATION
-------------------------
  Every optional component fails independently: missing TTS falls back to
  text, missing camera falls back to upload, a failed model download shows
  an actionable error, and depth or open-vocabulary failures keep existing
  detections. All pages carry the project disclaimer where relevant.

5. PRIVACY AND SECURITY
-----------------------
  - No data is written to disk by the app; images and text stay in memory.
  - Uploads are limited to PNG/JPEG, 10 MB, and 40 megapixels; validation
    happens before any full-resolution processing.
  - Streamlit XSRF protection is enabled and upload size is capped in
    .streamlit/config.toml; detailed server errors are hidden from clients.
  - No third-party fonts, scripts, or analytics are loaded at runtime.
  - Model downloads happen once; afterwards the app can run offline.
  - A public deployment has no built-in authentication; do not upload
    sensitive images to a shared instance.
